# Mainnet LSPS2 LSP nodes configured in open-source wallet / node-software source code

Method: GitHub code search (via authenticated `gh api search/code`) for `set_liquidity_source_lsps2`, `setLiquiditySourceLsps2`, `liquidity_source_lsps2`, `LDK_LSPS2`, `lsps2 "@" 9735`, `lsps2_service`, `lsps_client node_pubkey`, the Megalith pubkey, etc.; then raw-file reads of every hit and a regex sweep for 66-hex pubkeys. Pubkeys below are copied verbatim from the files, never reconstructed. Research date 2026-11-25.

## Which open-source wallets/apps configure an LSPS2 LSP for mainnet, and what are the exact node IDs and addresses?

### Takeaway
Only **two** distinct mainnet nodes are shipped as working LSPS2 (bLIP-52) defaults in open-source code: **Megalith LSP 2** `034066e29e402d9cf55af1ae1026cc5adf92eed1e0e421785442f53717ad1453b0@64.23.159.177:9735` (Alby Hub, lnurl-mint-rust, BitKiss, fluid-wallet, the Megalith example client, formerly zinqq) and, newly found, the **Stable Channels LSP** `0388948c5c7775a5eda3ee4a96434a270f20f5beeed7e9c99f242f21b87d658850@stablechannels.com:9735` (Stable Channels iOS/Android/desktop, zinqq's current default). A third, **LQwD Germany** `032c9c7648e471befa2dc2d093e0854dd138f2718c0ad93bd4411328b33d072918` (SaturnZap lists it at `3.68.244.94:26000`), was used as zinqq's LSPS2 primary from May to July 2026 and then removed. It did not answer from here. ZEUS and LDK Node Monday also give Olympus (`031b3013…`) to LDK Node as an LSPS2 source, but nothing shows that Olympus serves LSPS2.

### Cited Findings

**A. Megalith LSP 2 (operator: Megalith / MegalithicBTC). LSPS2 confirmed.**
- Pubkey `034066e29e402d9cf55af1ae1026cc5adf92eed1e0e421785442f53717ad1453b0`, address `64.23.159.177:9735`. This is Alby Hub's hard-coded mainnet fallback (`case "bitcoin": // Megalith LSP 2`) in `NewLDKService`. When the `LDK_LSPS2_ADDRESSES` env var is set, it overrides the default. Otherwise Hub first picks a `suggestion.Type == lsp.LSP_TYPE_LSPS2` entry from Alby's channel-suggestion API that matches the network. It is passed to `builder.SetLiquiditySourceLsps2(pubkey, address, nil)`, i.e. with no token. — [getAlby/hub lnclient/ldk/ldk.go](https://github.com/getAlby/hub/blob/master/lnclient/ldk/ldk.go)
- Alby Hub README: "`LDK_LSPS2_ADDRESSES`: Override the LSPS2 just-in-time (JIT) LSP provider for receiving … Expected format is a single `<pubkey>@<host>:<port>`." Config field `LDKLiquiditySourceLsps2 string envconfig:"LDK_LSPS2_ADDRESSES"`. — [getAlby/hub README.md](https://github.com/getAlby/hub/blob/master/README.md), [config/models.go](https://github.com/getAlby/hub/blob/master/config/models.go)
- Alby Hub's absolute opening-fee ceiling: `lsps2MaxOpeningFeeBaseMsat = 5_000_000` and `lsps2MaxOpeningFeePercent = 10`, whichever is greater. — [getAlby/hub ldk.go](https://github.com/getAlby/hub/blob/master/lnclient/ldk/ldk.go)
- Alby's live suggestion API (`GET https://getalby.com/api/internal/channel_suggestions`, called by Hub's `GetChannelPeerSuggestions`) lists exactly one mainnet `"type":"LSPS2"` entry when fetched on 2026-11-25: `"name":"Megalith LSP 2"`, `nodeAddress 034066e29e…1453b0@64.23.159.177:9735`, `minimumChannelSize 2501`, `maximumChannelSize 16000000`. Every other mainnet LSP in that list (Megalith 038a9e56…, Lnserver, Olympus by ZEUS, Magma by Amboss, B HODL) is `LSPS1`. — [Alby channel_suggestions API](https://getalby.com/api/internal/channel_suggestions); endpoint URL from [getAlby/hub alby/alby_service.go](https://github.com/getAlby/hub/blob/master/alby/alby_service.go)
- Backend definition (Alby's getalby.com repo; **private**, read through the user's GitHub access): `MegalithLsps2` with `type = "LSPS2"`, `network = "bitcoin"`, `lsp_name = "Megalith LSP 2"`, `public_channels_allowed = false`, `min_channel_balance_sat = 2501`, `max_channel_balance_sat = 16_000_000`, `channel_expiry_blocks = 13_140`. Terms: "Megalith will do its best to keep your channel open for at least 3 months." Of the 15 LSP files in `lib/lsp/`, only `megalith_lsps2.rb` and `megalith_mutiny_lsps2.rb` are LSPS2. — getAlby/getalby.com `lib/lsp/megalith_lsps2.rb` (private repo, no public URL)
- Megalith's own docs: mainnet LSPS2 node `034066e2…1453b0@64.23.159.177:9735`, "any token works", "Make sure your node is able to accept the payment within 60 seconds (ideally sooner)." — [Megalith docs: LSPS2 JIT channel for mobile clients](https://docs.megalithic.me/lightning-services/lsps2-get-a-just-in-time-channel-for-mobile-clients/)

The fee "is the larger of 1.4% of the payment and a minimum": 2,500 sats at 1 sat/vB for the first and second channel, 5,000 for the 3rd and 4th, 10,000 after that, "plus 507 sats for each sat/vB of on-chain fee above 1". **B. Stable Channels LSP (operator: Stable Channels / Tony Klausing, repo toneloc/stable-channels). LSPS2, new finding.**

### Inferences
- For an LDK Node / ldk-server client today, only two mainnet LSPS2 endpoints have evidence of working: Megalith LSP 2 (widely used and documented) and Stable Channels (`0388948c…@stablechannels.com:9735`, the default in two independent projects). Stable Channels is a small, single-operator service built around its USD-stable product. Its mainnet fee terms are not published in the repo.
- The Olympus LSPS2 configuration in ZEUS and Monday is probably opportunistic: it is wrapped in try/catch, and ZEUS has no JIT receive call. It should not be read as evidence that Olympus serves bLIP-52.
- LQwD Germany may have served LSPS2 in mid-2026, since zinqq made it the primary and checked for its route hint. It now appears unreachable or retired, which matches the LQWD-AI-Grid status.

### Gaps
- I did not run an LSPS2 `lsps2.get_info` handshake against Stable Channels or LQwD Germany (TCP only). Live LSPS2 support, the mainnet fee menu and the token policy of `0388948c…` remain unconfirmed by protocol.
- Why zinqq dropped LQwD in PR #167 is not stated.
- Fedi, Lexe, Blixt, Satsails, Bull Bitcoin, Primal, Nunchuk, Blitz, Mutiny, Fedimint gateway, BTCPay LDK plugin, LNbits and the Start9/Umbrel packages: code search found no LSPS2 configuration. These are either closed, use Breez/Spark/Lexe's own LSP, or are not LDK-Node based. I did not read each repo by hand.
- Winnow's earlier provider list ("Megalith Instant") is not in the public git history, which is squashed (232 commits, no Lightning commits), so the file could not be found.

## For each wallet, is the LSP JIT feature LSPS2 or a proprietary API? Are there multiple LSPS2 providers in any wallet's list?

### Takeaway
LDK-Node apps that call `set_liquidity_source_lsps2` plus `receive_via_jit_channel` (Alby Hub, Stable Channels, BitKiss, fluid-wallet, lnurl-mint-rust, OpenBazaar) and zinqq's own LSPS2 client use real LSPS2. ZEUS uses its proprietary Flow API for JIT, and Bittr uses its own node. No shipped wallet has more than one mainnet LSPS2 provider at a time. Alby Hub picks one (API-provided, else Megalith), and zinqq briefly had LQwD primary plus Megalith fallback.

### Cited Findings
- Alby Hub: one LSPS2 source. Order: env override, then the first matching LSPS2 suggestion from Alby's API, then the hard-coded Megalith. LDK Node supports one LSPS2 source at a time. — [getAlby/hub ldk.go](https://github.com/getAlby/hub/blob/master/lnclient/ldk/ldk.go)
- BitSov: "LDK Node has **one active LSPS2 client**. The list is a local provider registry". — [BitSov docs/LSPS2-LIQUIDITY.md](https://github.com/MindLink-ApS/BitSov-bitsov/blob/main/docs/LSPS2-LIQUIDITY.md)
- zinqq has a hand-rolled LSPS2 client in `src/ldk/lsps2/` (bLIP-52 wire format), because "`lightning-liquidity` … is not wrapped by `ldk-c-bindings`". From May to July 2026 it had primary/fallback failover (LQwD, then Megalith). Since PR #167 it has had a single LSP. — [zinqq PR #167](https://github.com/ConorOkus/zinqq/pull/167), [PR #148](https://github.com/ConorOkus/zinqq/pull/148)
- ZEUS: LSPS1 + LSPS2 + LSPS7 are all set to Olympus in embedded LDK. The JIT/wrapped-invoice default is the Flow API at `https://flow.zeuslsp.com`. — [ZeusLN/zeus SettingsStore.ts](https://github.com/ZeusLN/zeus/blob/master/stores/SettingsStore.ts)
- Bittr: "not yet using the full LSP2 specification". — [bittr BitcoinManager.swift](https://github.com/getbittr/bittr-ios-app/blob/main/ios/bittr/BitcoinManager.swift)
- Monday: mainnet list has only `olympus_mainnet`. The signet list has four entries. — [reez/Monday Constants.swift](https://github.com/reez/Monday/blob/main/LDKNodeMonday/Utilities/Constants.swift)

### Inferences
- A client wanting failover across LSPS2 providers must rebuild the node or carry its own LSPS2 client (as zinqq did). No open-source LDK-Node wallet found ships two mainnet LSPS2 providers at once.

### Gaps
- I did not confirm whether LDK Node upstream (late 2026) accepts several LSPS2 sources. BitSov's statement is the only source.

## Any LSPS2 tokens/API keys required and how they are obtained?

### Takeaway
No mainnet LSPS2 provider found needs a real token. Megalith accepts any string or none (Alby passes `nil`), and Stable Channels is configured with an empty token. Tokens show up only for the C= / "See" Mutinynet node (`4GH1W3YW`, `JZWN9YLW`, `T2MF3ZU5`).

### Cited Findings
- Megalith: "any token works". — [Megalith docs](https://docs.megalithic.me/lightning-services/lsps2-get-a-just-in-time-channel-for-mobile-clients/); "Token | any string works". — [lsps2-client-example README](https://github.com/MegalithicBTC/lsps2-client-example/blob/main/README.md); Alby Hub passes `nil`. — [ldk.go](https://github.com/getAlby/hub/blob/master/lnclient/ldk/ldk.go)
- Stable Channels default in zinqq: `VITE_LSP_TOKEN=` (empty). — [zinqq .env.example](https://github.com/ConorOkus/zinqq/blob/main/.env.example)
- zinqq PR #96: C= Mutinynet "requires access token `JZWN9YLW`". — [zinqq PR #96](https://github.com/ConorOkus/zinqq/pull/96)

### Inferences
- The token field can be left empty, or set to any placeholder, for both mainnet providers.

### Gaps
- No source documents a process for obtaining a token from any mainnet LSPS2 provider.
